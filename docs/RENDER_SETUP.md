# Original-footage render setup

Status: Phase 8 implementation, runtime acceptance deferred. Start the `renders` service with the media Compose package after foundation migrations and media configuration. Its command is `python -m app.renders.worker`. Existing deployment remains transitional; pushing this code does not demonstrate the new package has been deployed.

Save a canonical timeline revision, then choose Render MP4 on the timeline page. The request records the revision, snapshot hash and versioned preset. A retry after an uncertain request uses the same command UUID; a new explicit render after a terminal failure creates a new job. Jobs report stage and completed occurrences, not estimated encoding percentages. Cancel is cooperative and publication is fenced against expired/cancelled leases. Lease crashes can retry; deterministic validation failures do not loop.

The `h264-sdr-v1` preset reads hash-verified originals, never proxies. It requires source and sequence FPS/dimensions to match, verified CFR timing, even dimensions, progressive square pixels without rotation, and explicit Rec.709 limited-range 8-bit yuv420p. HDR, wider chroma, higher bit depth, unknown color, scaling, mixed FPS and multichannel audio fail explicitly. These are remaining capability gaps, not evidence of full professional camera compatibility. Timeline timing preparation also retains its bounded scan limitation.

Video cuts count decoded source frames with exclusive out boundaries. Audio uses the pinned first stream's source offset, 48 kHz stereo, cumulative rounded sequence sample boundaries, optional mono duplication, silence padding and saved gain/mute. Other audio streams are not mixed. Each cut produces lossless raw video and floating PCM scratch; concatenation uses bytes rather than rounded container timestamps. Final delivery encodes H.264 CRF 18 slow and AAC 320 kbps once. This preserves original resolution within the supported subset, but is a lossy delivery encode. No bit-identical or Premiere-equivalent fidelity claim is made.

FFmpeg must provide rawvideo, pcm_f32le, libx264 and AAC encoders. Probe and encoder preflight run on the worker. Frame count, dimensions, FPS and audio length are checked before publication; audio duration allows one AAC packet of padding. These metadata checks are not independent perceptual or frame-content acceptance. Source hashes are checked again and the artifact SHA-256 is stored with provenance.

Scratch estimate is `frames * width * height * 1.5 + stereo_samples * 8` bytes. Preflight reserves twice this estimate for cut assembly/output and enforces the configured work limit while processing. At 4K/24, raw video alone is about 285 MiB per second. The default 2 GiB budget therefore supports only short fixtures. Increase explicit storage/time limits for an authorized workload; quality is never reduced to fit. This simple CPU reference path is not an efficient terabyte implementation. Losslessly compressed or streaming scratch is a future optimization requiring the same fidelity checks.

The API sees the artifact mount read-only. Completed artifacts remain until operator retention cleanup; known failed attempts remove their own directory. Uncertain database publication and process crashes may retain orphan attempts. Before operator cleanup, inspect job state/lease and preserve active or successfully published attempts. No automatic garbage collector is provided in this phase.

Authenticated project members obtain five-minute job-scoped download tickets. File responses stream with range support without collecting movies into a browser Blob. Tickets are bearer credentials: do not log query strings or share links. The download checks size/mtime, not a full rehash on every range request; the publication checksum enables independent verification. Operator-controlled artifact storage is a trust boundary. A new request after ticket expiry needs a new ticket.

Required deferred acceptance: actual source-to-output frame comparison, fractional FPS and repeated cuts, delayed/early audio and impulse sync, mono/stereo/mute/gain, AAC padding, 4K output fidelity, changed/missing originals, disk exhaustion, cancellation during decode/hash/encode, expired leases/restarts, cross-project denial, interrupted/range downloads and immutable originals. The added tests are preparation, not a passing result. Complete Phase 9 workflow and release gates remain required.

Implementation references: [FFmpeg trim and timestamp filters](https://ffmpeg.org/ffmpeg-filters.html#trim), [audio sample trimming](https://ffmpeg.org/ffmpeg-filters.html#atrim) and [raw media formats](https://ffmpeg.org/ffmpeg-formats.html). Encoding fidelity must be measured against original frames/audio and the approved timeline.
